# Детектор ИИ-текста (русский язык)

[English](README.md) · **Русский**

Определяет, написан ли текст человеком или сгенерирован языковой моделью. Считает
вероятность и показывает, на какие признаки она опирается. Работает локально, без
обращения к внешним сервисам.

> Это вероятностная оценка, а не доказательство авторства. Раздел
> [«Ограничения»](#ограничения) — обязательно к прочтению.

## В двух словах

Под одним интерфейсом четыре модели:

- **v4** — боевая, по умолчанию. Дообученный `ai-forever/ruBert-base` (178M),
  переобученный с добавлением текстов Llama 3.1 и Mistral. Шире всех по покрытию
  генераторов.
- **v3** — дообученный `ruBert-base`, прежняя боевая. Консервативнее v4, оставлена
  как откат.
- **v2** — дообученный `rubert-tiny2` (29M). Лёгкий и быстрый, но слабее на коротком.
- **v1** — восемь статистических признаков + калиброванный GradientBoosting. Быстрый
  и интерпретируемый; языковая модель используется только для одного признака
  (перплексии).

Переключение версий — флагом `--model` (CLI), параметром `?model=` (сервис) или
клавишей в TUI. Откат боевой версии на v3 — одна строка `DEFAULT_VERSION = "v3"`
в `aidetector/transformer_score.py`.

## Установка

Нужен **Python 3.10–3.12** (на 3.13 ставить нельзя: пины `torch 2.4.1` /
`sklearn 1.5.2` / `numpy 1.26.4` не имеют под него колёс, а модели `models/*.joblib`
пиклены `sklearn 1.5.2` — версию стека не меняем). Рекомендуется 3.12. Если в системе
несколько Python, укажите нужный: `PYTHON=python3.12 ./setup.sh`. Скрипт создаёт
виртуальное окружение, ставит зависимости и скачивает боевую модель v4:

```bash
git clone https://github.com/k1y0miiii/ru-ai-text-detector.git
cd ru-ai-text-detector
./setup.sh
source venv/bin/activate
```

Модель перплексии для v1 (`ai-forever/rugpt3small_based_on_gpt2`) подтянется с
HuggingFace автоматически при первом запуске. Базовые модели для переобучения
ставятся отдельно: `./setup.sh --train`.

## Запуск

Командная строка:

```bash
python apps/detect_cli.py samples/sample_ai_1.txt          # один файл, модель v4
python apps/detect_cli.py --text "проверяемый текст"        # текст из аргумента
python apps/detect_cli.py --text "..." --model v1           # другая версия
python apps/detect_cli.py --dir samples/                    # вся папка + сверка с labels.json
```

HTTP-сервис:

```bash
uvicorn apps.app:app --reload
# POST /detect  {"text": "..."}   [?model=v1|v2|v3|v4]
curl -s localhost:8000/detect -H 'Content-Type: application/json' \
     -d '{"text":"проверяемый текст"}'
```

Ответ содержит вероятность, вердикт по калиброванному порогу и разбивку по
признакам v1 (её показываем всегда — это объясняет, почему текст так оценён).

Терминальный интерфейс с поабзацной картой документа (`.txt`, `.docx`, `.pdf`):

```bash
python apps/detector_tui.py                                 # дерево файлов из samples/
python apps/detector_tui.py --text samples/test_mixed.docx  # headless-отчёт без UI
```

## Как это работает

Общая схема: `текст → признаки или эмбеддинги → классификатор → вероятность → порог`.
Целевая метрика с самого начала — не точность, а recall при ложноположительных
не выше 3% на генераторе, которого не было в обучении. Ложно обвинить человека
дороже, чем пропустить ИИ.

### Признаки v1

Восемь величин (`aidetector/features.py`):

- `perplexity` — насколько текст предсказуем для языковой модели; у ИИ обычно ниже.
- `perplexity_std` — разброс перплексии по предложениям; у человека выше (то банально,
  то неожиданно), у ИИ ровно.
- `rank_entropy` — энтропия ранга токенов в распределении модели (подход GLTR);
  у человека «неожиданных» токенов больше. Главный сигнал.
- `burstiness` — разброс длин предложений.
- `mean_sent_len` — средняя длина предложения.
- `mattr` — лексическое разнообразие, не зависящее от длины (moving-average TTR).
- `cliche_rate` — частота шаблонных связок («важно отметить», «таким образом»).
- `punct_variety` — разнообразие пунктуации.

Наибольший вклад дают `rank_entropy` (0.33) и `perplexity_std` (0.22) — то, что
отличает ровный машинный текст от рваного человеческого.

### Трансформеры v2–v4

Полный fine-tune энкодера в бинарный классификатор, вероятности калиброваны
изотонической регрессией. Порог — length-aware: на коротких фрагментах (меньше
40 слов) он строже, потому что там хвост ложных срабатываний нестабилен. Так
ложноположительные держатся ниже 3% на всех длинах.

### Карта документа

Прямой прогон детектора по абзацам не годится: на тексте короче 200 символов v1
ненадёжен (ложные срабатывания доходят до 0.24), а половина реальных абзацев
короче. Поэтому `aidetector/document_scan.py` считает на скользящих окнах ~150 слов,
а показывает результат на абзацах. Перед этим отсекаются титул, оглавление, список
литературы и таблицы (по разметке docx), чтобы канцелярит и данные не попадали под
оценку как проза.

## Версии и метрики

Хронология — про методологию: каждый переход обоснован замером предела предыдущей
версии. Подробности в [docs/DESIGN_DECISIONS.md](docs/DESIGN_DECISIONS.md).

**v1 — признаки (held-out, тексты ≥200 символов).** Машинный класс собран из трёх
генераторов, чтобы детектор не затачивался под один.

| Метрика | Значение |
|---|---|
| ROC-AUC | 0.877 |
| Порог решения | 0.86 (под FPR ≤ 3%) |
| FPR на людях | 0.030 |
| Recall по ИИ | 0.465 |
| Precision @0.86 | ≈0.94 |

Предел признаков: на коротких текстах сигнал вырождается, на сильных генераторах
(GPT-4) recall падает до 0.13. Добавление GPT-4 в обучение recall почти не сдвинуло
(0.13 → 0.16) — слепота оказалась свойством признакового пространства, а не нехватки
данных. Это и стало поводом перейти к обучаемому представлению.

**v3 против v1/v2 (фрагмент 40 слов, невиданные генераторы).**

| | v1 | v2 | v3 |
|---|---|---|---|
| rec @FPR 3% | 0.53 | — | 0.85 |
| ROC-AUC на GPT-4 | 0.81 | 0.81 | 0.96 |
| FPR на людях (длинные) | 0.030 | 0.023 | 0.015 |
| скорость на CPU, мс/текст | ~5 | 2 | 26 |

**v4 — переобучение v3 с текстами Llama 3.1 и Mistral.** Менялись только данные,
рецепт обучения тот же.

| Генератор | v3 → v4 |
|---|---|
| holdout Llama | 0.45 → 0.94 |
| holdout Mistral | 0.51 → 0.92 |
| GPT-4 (невиданный) | 0.74 → 0.77 |
| saiga | 0.90 → 0.82 |

Цена шире покрытия: v4 менее консервативен (test-FPR 0.007 → 0.023, остаётся в
бюджете ≤3%). Порог v4 — 0.834 для обычной длины и 0.889 для фрагментов короче
40 слов.

## Структура проекта

```
aidetector/      ядро-библиотека (импортируемый пакет)
  features.py            извлечение 8 признаков (v1)
  transformer_score.py   инференс v2/v3/v4, калибровка, length-aware порог
  document_scan.py       поабзацная карта документа на окнах
  extract_text.py        текст из .txt/.docx/.pdf
  genre_classify.py      эвристическое определение жанра
  dataset.py featcache.py perturb.py   данные, кэш фич, возмущения
  paths.py               пути к models/ и data/
apps/            точки входа
  app.py                 FastAPI-сервис POST /detect
  detect_cli.py          CLI
  detector_tui.py        терминальный интерфейс
  show_flagged.py docx_v2.py
training/        сбор данных, обучение, калибровка (v1–v4)
evaluation/      оценка качества, замеры, скорость
tests/           регрессия сегментации
models/          артефакты: model.joblib, *_calibrator.joblib, threshold_*.json
                 (веса v2/v3/v4 — не в git, ставятся через setup.sh)
data/            метрики прогонов; корпуса собираются скриптами training/
samples/         тестовые тексты (см. samples/README.md)
docs/            DESIGN_DECISIONS.md — хроника решений
```

Артефакты модели и данные ищутся через `aidetector/paths.py` независимо от текущего
каталога. Запускать скрипты из корня репозитория.

## Переобучение

```bash
./setup.sh --train                 # базовая модель ai-forever/ruBert-base в bases/
python training/prepare_data.py    # собрать корпус в data/ (см. docs)
python training/train_v4.py        # дообучить v4
python training/calibrate_v4.py    # калибровать порог
python training/evaluate_v4.py     # приёмка на held-out
```

Полный конвейер v4 одной командой — `training/run_v4_pipeline.sh`. Корпуса собираются
из сторонних датасетов (RuATD, ru_turbo_saiga, ru_instruct_gpt4) и локальной
генерации (Ollama); в репозиторий они не входят из-за лицензий.

## Ограничения

- Это вероятностная оценка, а не доказательство. На основании только детектора
  нельзя принимать дисциплинарные решения.
- Любой детектор ошибается, особенно на текстах неносителей языка и на коротких
  фрагментах. Порог калиброван под ≤3% ложных обвинений, но не под ноль.
- v4 завышает оценку на гуманитарных и лингвистических академических работах
  (их стиль близок к обучающим ИИ-текстам). Для таких текстов есть режим
  согласованности двух моделей и переключение на v3.
- Гуманизированный (переписанный вручную) ИИ и короткие вставки в человеческий
  текст ловятся плохо.
- На реальных дипломах детектор закономерно подсвечивает шаблонные места (описания
  по трафарету, канцелярит введения). Подсветка означает «формализованное место,
  посмотреть глазами», а не обвинение.
