# AI text detector (Russian language)

**English** · [Русский](README.ru.md)

Tells whether a text was written by a human or generated by a language model. It
returns a probability and shows which signals it relied on. Everything runs locally,
with no calls to external services.

The project targets Russian text; the Russian README is the primary one:

> This is a probabilistic estimate, not proof of authorship. Read the
> [Limitations](#limitations) section.

## Overview

Four models behind one interface:

- **v4** — production default. Fine-tuned `ai-forever/ruBert-base` (178M), retrained
  with added Llama 3.1 and Mistral texts. The widest generator coverage.
- **v3** — fine-tuned `ruBert-base`, the previous production model. More conservative
  than v4, kept as a fallback.
- **v2** — fine-tuned `rubert-tiny2` (29M). Light and fast, weaker on short text.
- **v1** — eight statistical features plus a calibrated GradientBoosting classifier.
  Fast and interpretable; a language model is used only for one feature (perplexity).

Switch versions with `--model` (CLI), `?model=` (service), or a key in the TUI. To
roll the default back to v3, change one line `DEFAULT_VERSION = "v3"` in
`aidetector/transformer_score.py`.

## Install

Python 3.10+ required. The script creates a virtual environment, installs
dependencies, and downloads the production v4 model:

```bash
git clone https://github.com/k1y0miiii/ru-ai-text-detector.git
cd ru-ai-text-detector
./setup.sh
source venv/bin/activate
```

The v1 perplexity model (`ai-forever/rugpt3small_based_on_gpt2`) is pulled from
HuggingFace automatically on first run. Base models for retraining are installed
separately: `./setup.sh --train`.

## Usage

Command line:

```bash
python apps/detect_cli.py samples/sample_ai_1.txt          # one file, model v4
python apps/detect_cli.py --text "text to check"            # text from an argument
python apps/detect_cli.py --text "..." --model v1           # a different version
python apps/detect_cli.py --dir samples/                    # whole folder + check vs labels.json
```

HTTP service:

```bash
uvicorn apps.app:app --reload
# POST /detect  {"text": "..."}   [?model=v1|v2|v3|v4]
curl -s localhost:8000/detect -H 'Content-Type: application/json' \
     -d '{"text":"text to check"}'
```

The response has the probability, a verdict against the calibrated threshold, and a
breakdown of the v1 features (always shown — it explains why the text scored as it did).

Terminal UI with a per-paragraph document map (`.txt`, `.docx`, `.pdf`):

```bash
python apps/detector_tui.py                                 # file tree from samples/
python apps/detector_tui.py --text samples/test_mixed.docx  # headless report, no UI
```

## How it works

The pipeline is `text → features or embeddings → classifier → probability → threshold`.
From the start the target metric is not accuracy but recall at a false-positive rate
no higher than 3% on a generator that was not in training. Falsely accusing a person
costs more than missing an AI text.

### v1 features

Eight values (`aidetector/features.py`):

- `perplexity` — how predictable the text is for a language model; usually lower for AI.
- `perplexity_std` — variance of perplexity across sentences; higher for humans (now
  trite, now surprising), flat for AI.
- `rank_entropy` — entropy of token rank in the model distribution (GLTR approach);
  humans produce more surprising tokens. The strongest signal.
- `burstiness` — variance of sentence lengths.
- `mean_sent_len` — mean sentence length.
- `mattr` — length-invariant lexical diversity (moving-average TTR).
- `cliche_rate` — frequency of template connectives.
- `punct_variety` — punctuation variety.

The largest contributions come from `rank_entropy` (0.33) and `perplexity_std` (0.22),
which separate flat machine text from bursty human text.

### Transformers v2–v4

A full fine-tune of the encoder into a binary classifier, with probabilities
calibrated by isotonic regression. The threshold is length-aware: stricter on short
fragments (under 40 words), where the false-positive tail is unstable. This keeps the
false-positive rate under 3% across all lengths.

### Document map

Running the detector paragraph by paragraph does not work: on text shorter than 200
characters v1 is unreliable (false positives reach 0.24), and half of real paragraphs
are shorter. So `aidetector/document_scan.py` scores sliding windows of ~150 words and
displays results on paragraphs. Before that it drops the title page, table of
contents, bibliography, and tables (from the docx markup), so boilerplate and data are
not judged as prose.

## Versions and metrics

The history is about methodology: each step is justified by measuring the ceiling of
the previous version. Details in [docs/DESIGN_DECISIONS.md](docs/DESIGN_DECISIONS.md).

**v1 — features (held-out, texts ≥200 characters).** The machine class is built from
three generators so the detector does not overfit to one.

| Metric | Value |
|---|---|
| ROC-AUC | 0.877 |
| Decision threshold | 0.86 (for FPR ≤ 3%) |
| FPR on humans | 0.030 |
| Recall on AI | 0.465 |
| Precision @0.86 | ≈0.94 |

The feature ceiling: the signal degrades on short text, and recall on strong
generators (GPT-4) drops to 0.13. Adding GPT-4 to training barely moved recall
(0.13 → 0.16) — the blindness turned out to be a property of the feature space, not a
lack of data. That justified moving to a learned representation.

**v3 vs v1/v2 (40-word fragment, unseen generators).**

| | v1 | v2 | v3 |
|---|---|---|---|
| rec @FPR 3% | 0.53 | — | 0.85 |
| ROC-AUC on GPT-4 | 0.81 | 0.81 | 0.96 |
| FPR on humans (long) | 0.030 | 0.023 | 0.015 |
| CPU speed, ms/text | ~5 | 2 | 26 |

**v4 — v3 retrained with Llama 3.1 and Mistral texts.** Only the data changed; the
training recipe stayed the same.

| Generator | v3 → v4 |
|---|---|
| holdout Llama | 0.45 → 0.94 |
| holdout Mistral | 0.51 → 0.92 |
| GPT-4 (unseen) | 0.74 → 0.77 |
| saiga | 0.90 → 0.82 |

The cost of wider coverage: v4 is less conservative (test FPR 0.007 → 0.023, still
within the ≤3% budget). The v4 threshold is 0.834 for normal length and 0.889 for
fragments under 40 words.

## Project layout

```
aidetector/      core library (importable package)
  features.py            8-feature extraction (v1)
  transformer_score.py   v2/v3/v4 inference, calibration, length-aware threshold
  document_scan.py        per-paragraph document map over windows
  extract_text.py        text from .txt/.docx/.pdf
  genre_classify.py      heuristic genre detection
  dataset.py featcache.py perturb.py   data, feature cache, perturbations
  paths.py               paths to models/ and data/
apps/            entry points
  app.py                 FastAPI service POST /detect
  detect_cli.py          CLI
  detector_tui.py        terminal UI
  show_flagged.py docx_v2.py
training/        data collection, training, calibration (v1–v4)
evaluation/      quality evaluation, measurements, speed
tests/           segmentation regression
models/          artifacts: model.joblib, *_calibrator.joblib, threshold_*.json
                 (v2/v3/v4 weights are not in git, installed via setup.sh)
data/            run metrics; corpora are built by the training/ scripts
samples/         test texts (see samples/README.md)
docs/            DESIGN_DECISIONS.md — decision log
```

Model artifacts and data are resolved through `aidetector/paths.py` regardless of the
working directory. Run the scripts from the repository root.

## Retraining

```bash
./setup.sh --train                 # base model ai-forever/ruBert-base into bases/
python training/prepare_data.py    # build the corpus into data/ (see docs)
python training/train_v4.py        # fine-tune v4
python training/calibrate_v4.py    # calibrate the threshold
python training/evaluate_v4.py     # acceptance on held-out
```

The full v4 pipeline in one command is `training/run_v4_pipeline.sh`. Corpora are built
from third-party datasets (RuATD, ru_turbo_saiga, ru_instruct_gpt4) and local
generation (Ollama); they are not shipped in the repository because of licensing.

## Limitations

- This is a probabilistic estimate, not proof. Do not base disciplinary decisions on
  the detector alone.
- Any detector makes mistakes, especially on text by non-native speakers and on short
  fragments. The threshold is calibrated for ≤3% false accusations, not for zero.
- v4 overrates text in humanities and linguistics academic writing (its style is close
  to the training AI texts). For such texts there is a two-model agreement mode and a
  switch to v3.
- Humanized (manually rewritten) AI and short insertions into human text are detected
  poorly.
- On real theses the detector predictably highlights boilerplate (templated
  descriptions, the formulaic language of an introduction). A highlight means "a
  formalized passage, look at it yourself", not an accusation.
